# Raw-SQL usage allowlist — every production file matching the shared `rawSql`
# regex in route-class-patterns.json (`\$(queryRaw|executeRaw)(Unsafe)?\b`) MUST
# be listed here with a purpose (>=10 chars). Enforced by
# scripts/checks/check-raw-sql-usage.mjs, registered in scripts/pre-pr.sh.
#
# Format: path # purpose
#   - path: repo-relative, exactly as reported by the seeding grep below.
#   - purpose: what the raw SQL in this file is for (>=10 chars), reviewer-facing.
#   A leftover third `#`-segment (the former optional per-file marker-count
#   suffix) is a parse error — that grammar was removed along with the marker
#   mechanism; see below.
#
# --- Two-layer design (see the "unforgeable SQL text for raw-SQL calls" plan
#     and review log under docs/archive/review/, C3) ---
# Layer 1 (this file): every matching file must be allowlisted with a purpose;
#   a listed file that no longer matches the regex fails as STALE_EXEMPT.
# Layer 2 (check-raw-sql-usage.mjs, ts-morph AST pass, independent of Layer 1,
#   unconditional — fires on allowlisted files too): the runtime guarantee that
#   SQL text reaching an Unsafe call is either a literal or produced by
#   `renderSql()` from a genuine, runtime-verified value lives in
#   src/lib/prisma/raw-sql.ts (a module-private WeakMap adjudicates which
#   values are real). This gate enforces only the SYNTAX the runtime cannot
#   see: every occurrence of a sensitive name (`renderSql`, `trustedSql`,
#   `sqlIdentifier`, `joinSql`, the `$queryRaw`/`$executeRaw` family, any
#   `@prisma/*` import, `$extends`) is judged by its syntactic POSITION alone —
#   never by what it is bound to. An Unsafe call's first argument must be a
#   string literal, a no-substitution template, or a direct `renderSql(...)`
#   call; nothing wrapped around or appended to it. The former inline-comment
#   marker mechanism (a lexical span tracker that trusted a comment naming a
#   validator, without checking the validator ran) is removed entirely —
#   superseded by the runtime-checked opaque values.
#
# --- Baseline (re-verified at implementation time, 2026-07-04) ---
# Zero call sites in this inventory interpolate user- or tenant-derived input
# into a raw SQL string. Unsafe variants use EITHER (a) static SQL + `$N` bound
# parameters (the overwhelming majority — maintenance audit-chain-verify,
# audit-outbox-worker, audit-chain-verify-worker.ts), OR (b) interpolate only
# identifiers from the closed retention-gc registry (sweep.ts —
# table/cutoffColumn/keyColumns names validated at worker boot by
# `validateRegistry()` in retention-gc-worker/index.ts, never derived from a
# request; migrated to `sqlIdentifier()` under the plan above).
# scripts/migrate-account-tokens-to-encrypted.ts interpolates a fixed
# compile-time literal (`BATCH_SIZE`, a hardcoded conditional `WHERE` clause
# string) and column names from a closed 3-element literal set defined in the
# same function — never user/tenant input either, migrated to `trustedSql`.
# Non-Unsafe `$executeRaw`/`$queryRaw` tagged-template calls are Prisma-
# parameterized by construction (interpolated expressions become bound
# parameters, not string-concatenated SQL); Layer 2's PRISMA_IMPORT/RAW_METHOD
# rules still constrain how the tag itself and Prisma's other exports may be
# used (FR4) — the injection-shaped risk the former Layer 2 targeted narrowly
# (the Unsafe variants' plain string/argument list) is now closed at the value
# level by `src/lib/prisma/raw-sql.ts`, not by a per-file marker count.
#
# Seeded via (R42 refresh, re-run at implementation start, 2026-07-04):
#   grep -rlE '\$(queryRaw|executeRaw)(Unsafe)?\b' src scripts --include='*.ts' --include='*.tsx' \
#     | grep -vE '\.test\.|__tests__|manual-tests|/e2e/' | sort
# → 23 files. The 22 advisory-lock call sites that formerly inlined
#   `pg_advisory_xact_lock` now call the shared `advisoryXactLock()` helper in
#   src/lib/tenant-rls.ts, so those files no longer emit raw SQL and were dropped
#   from this allowlist (the helper's raw SQL is covered by the tenant-rls.ts
#   entry below). See bypass-rls-tx-callback-form plan.
