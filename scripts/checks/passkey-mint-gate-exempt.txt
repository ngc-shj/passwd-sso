# Passkey-mint-gate exempt allowlist (check-passkey-mint-gate.sh)
#
# Route files that mint or re-mint a token but are INTENTIONALLY exempt from a
# direct `passkeyEnforcementBlocks` call. Three kinds of exemption apply:
#   1. Gated through a parent token: the mint is reachable only behind a
#      different token that is itself passkey-gated per use.
#   2. Gated per use in the credential's validator: the mint route's own
#      bearer is validated by a function that runs the per-use gate
#      (`passkeyGateBlocks`) before the mint, so a dead `passkeyEnforcementBlocks`
#      call here would be redundant.
#   3. Gated inline in the mint or refresh library function itself, after
#      replay validation and before the mint/rotation.
#
# One repo-relative path per line. Lines beginning with `#` are comments.
# Every entry MUST state, in a trailing comment, why a direct gate does not
# apply (plan R42 — explicit classification, not silent omission).
#
# Adding a route here is a security decision — it must be justified, not a
# convenience to silence the guard. The default answer for a new mint route is
# "add passkeyEnforcementBlocks", NOT "add to this file".

src/app/api/mcp/token/route.ts # passkey gate moved into exchangeRefreshToken/exchangeCodeForToken (oauth-server.ts) AFTER replay validation, BEFORE mint
src/app/api/mobile/token/refresh/route.ts # passkey gate moved into refreshIosToken (mobile-token.ts) AFTER replay validation
src/app/api/extension/token/refresh/route.ts # gated per use in validateExtensionToken (C5), before the mint
